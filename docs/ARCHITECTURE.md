# Architecture

The map of Fieldbook: what every file is, what it does, and how it fits. Written
for a reader who does not write code.

Fieldbook watches the funders and organisations the Civic Literacy Initiative
follows, captures every funding call and project report as a plain text file in
this repository, reads the stated facts out of each with one bounded AI step, and
publishes the calls as an RSS feed and a searchable dashboard. **This repository
is the database.** There is no server and no database engine. Each item is one
file in the tree, and `github.com` renders it directly.

## How to use this file, and the rule that keeps it honest

Every file in `src/` opens with a short plain-language description of itself, and
every file has an entry below. **A pull request that adds or changes a file under
`src/` must update this map in the same pull request**, or the documentation
guard in CI fails it. A genuinely doc-irrelevant change can opt out by putting
`docs: n/a` in the pull request body, and that should be rare.

This is deliberate. Documentation that is optional falls behind the code within
weeks. Documentation the build refuses to merge without cannot.

**Writing an entry.** One or two sentences, no jargon, saying what the file is and
how it fits. Say what it is for, not how it is implemented. If a reader would have
to already know the codebase to understand the entry, rewrite it.

## The shape of the whole thing

The pipeline runs on a schedule and is almost entirely plain rules. Exactly one
step uses a model.

```
fetch -> normalize -> archive -> store -> extract -> validate -> write -> publish
 [det]     [det]       [det]     [det]   [AI+det]     [det]      [det]     [det]
                         |                    |
                    capture here         the only AI step
```

`[det]` marks a deterministic step: a plain rule or lookup, the same every time.
The single `[AI]` step reads a source's prose and writes a command naming the
facts it found; a deterministic builder turns that command into a record. The raw
fetched text is committed **before** anything reads it, so every card can be
rebuilt from the archive at any time.

## The files that exist today

The pipeline modules below are not built yet. This section lists what is in the
repository now; each row is filled in by the pull request that creates the file.

### Project configuration

| File | What it is |
|---|---|
| `pyproject.toml` | The project's definition: its name, the Python version it needs, the libraries it uses, and the settings for the tools that check the code. |
| `uv.lock` | The exact version and fingerprint of every library, so this machine, a teammate's, and GitHub all install the identical thing. Generated by `uv`, never edited by hand. |
| `mise.toml` | Which Python version this project runs on, and the named tasks. `mise run check` is the quality gate; `mise run setup` prepares a fresh clone. |
| `.python-version` | The Python version, for tools that read this file instead of `mise.toml`. |
| `.pre-commit-config.yaml` | Checks that run on your own machine before a commit or push: formatting and linting on commit, the commit-message format, the full test suite on push, and blocks on private keys and oversized files. |
| `.gitignore` | What git ignores. Includes the secret patterns that must never be committed. |

### Rules and records

| File | What it is |
|---|---|
| `constitution.md` | The six things that never change without a founder's written approval. The hard box. |
| `AGENTS.md` | The rules any AI coding agent must follow here, in the open format that Claude, Codex, and Copilot all read. |
| `CLAUDE.md` | The build brief, importing `AGENTS.md` so there is one shared source of rules. |
| `docs/ARCHITECTURE.md` | This file. The map. |
| `docs/DECISIONS.md` | Numbered decision records: why the system is built this way, and what each choice costs. Immutable and additive. |
| `docs/BUGS.md` | Every defect found and how it was fixed, with the test that now guards it. |
| `docs/ACTIVITY.md` | The journal: what was done, and when. |
| `issues/` | One short plain-English specification per pull request, written and approved before any code. |

### Automation

| File | What it is |
|---|---|
| `.github/workflows/ci.yml` | The quality gate on GitHub. Runs the same checks as `mise run check` on every pull request, plus the dependency audit and the documentation guard, and reports pass or fail. |
| `.github/workflows/scorecard.yml` | The OpenSSF Scorecard, which grades this repository's own security posture weekly. |
| `.github/dependabot.yml` | Watches for library and action updates and raises them as reviewable pull requests, on a delay rather than the day they appear. |
| `.claude/settings.json` | Shared agent configuration: the hook that refuses to end a working session while the quality gate is failing, and the rules restricting what an agent may do here. |

### The package

| File | What it is |
|---|---|
| `src/field_monitoring_pipeline/__init__.py` | Marks the folder as the project's Python package. Empty for now; the pipeline modules land here from PR 2 onward. |
| `tests/__init__.py` | Marks the tests folder as a package so the test runner can find it. |
| `tests/test_placeholder.py` | A single trivial test, so the test suite and the quality gate have something to run before any real code exists. |
