# ADR-0022 — The gate is the four standard checks; the rest was over-engineering [decision]
**Status:** Accepted (2026-08-31). **Owner:** CLI.
**Context.** A member of CLI reviewed the setup and found it had drifted into custom machinery guarding risks this project does not face, in places where a standard tool already covers the case. Three specifics. The lockfile agreement check duplicated what uv does for nothing: uv refuses to run when `pyproject.toml` and `uv.lock` disagree, verified by breaking the file deliberately and watching it refuse. A vulnerability scanner is the wrong mechanism at this scale: pinning an exact version means a version changes only when a person changes it, and that change arrives as a pull request where it can be questioned. And a rule requiring the architecture map to change whenever a covered file changes produces false positives by design, because code often changes below the level an entry describes, and a check that cries wolf trains people to ignore it. The wider point stands over all three: this is an open source project with no secrets and no personal data, and the risk actually being defended against is code reaching `main` without the maintainer's approval, not a supply-chain attack.
**Decision.** `mise run verify` is the four checks a gate normally is: formatting checked, lint, strict type-check, tests. The lockfile check, the vulnerability scan, the file size script, and the documentation guard script are removed, and `pip-audit` is dropped as a dependency. Every dev tool is pinned to an exact version rather than a range. `docs/ARCHITECTURE.md` stays, because a handover to two the handover is a stated requirement rather than a hypothetical risk, but nothing enforces it mechanically: keeping it current is a working rule checked by a review pass before pushing.
**Consequences.** Nothing custom for a new developer to learn; the gate is what a Python gate normally is. Dependency updates become a deliberate, discussed act rather than a stream of automated proposals or scanner findings. Two things are given up. There is no automatic warning when a vulnerability is found in a version already pinned, for which the Dependabot alerts repository setting is free cover and remains open for CLI to turn on. And there is no mechanical reminder to keep the architecture map current, which now rests on judgement. Both accepted. Supersedes the parts of [ADR-0004](0004-clean-as-you-code-machine-gate.md) and [ADR-0021](0021-every-check-runs-on-the-maintainers-machine.md) that added these checks. The standing lesson recorded alongside it: ask what the common pattern is, and whether this project needs it, before building a guard for a risk nobody here has hit.
