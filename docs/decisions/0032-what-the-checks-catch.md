# ADR-0032 — Which fields carry evidence, and what the checks actually catch [decision]
**Status:** Accepted (2026-09-03). **Owner:** CLI.
**Context.** The rule as written said every field is a value and a quote, and no code could satisfy it. A quote is only meaningful where a value is copied out of a page's prose. A type is a choice from a fixed list, a topic comes from this project's own tag file, a link is known from the capture before any model sees the item, and a title is the page's own heading. None of those is a sentence copied from the source, and demanding one for them would be asking for evidence of a kind that does not exist. Measurement made a second problem plain. A quote that satisfies the substring check can still be attached to a value it does not support: on a page stating grants of one to two thousand, a claimed budget of five million passed, because the quote was a real sentence. The design documents describe the quote check as making fabrication impossible to represent, which is true of unsourced fabrication and false of sourced fabrication.
**Decision.** Five fields carry a stored quote: budget, summary, eligibility, area and timing. Title is grounded differently, by having to be a whole line of the source rather than any substring of it, so a title cannot be assembled from scattered words. Type and the open basis are checked against fixed lists. Topics are assigned deterministically at a later slice and never by the model. The link is taken from the capture and the model has no flag for it. Funder is a claim drawn from the page's prose and is deliberately left ungrounded in phase one, which is a scope decision rather than an oversight and is recorded here so the slice that matches one call across sources knows what it is standing on. Where a value contains a number of two or more digits, that number must be supported, and how strictly depends on what the field is. A budget is the figure itself, so its number must appear in the budget's own quote. Every other quoted field is prose about the whole item, so its numbers must appear somewhere in the source rather than in one sentence. That split was measured rather than reasoned: holding a summary to its own sentence refused two runs in three on a real page, every time because the summary named the year of an election that the page discusses throughout, and the looser rule still refuses a figure the page never states anywhere. And the wording is corrected: these checks catch invention, not misattribution. Misattribution is caught only where a value can be read back out of its own evidence, which is the timing and the budget. It is not caught for the summary, the eligibility and the area, and it is not caught for the type either: checking against a fixed list refuses a kind nobody offers, and says nothing about whether the right kind was chosen. That was measured rather than reasoned. The same model reading the same page on two occasions called it a grant once and a request for proposals the other time, and both are on the list, so both passed. The propose, challenge and confirm pass is what addresses all four.
**Consequences.** The rule in `AGENTS.md` becomes something the code can satisfy and a reviewer can count. The most consequential figure on a card, the money, gains a deterministic check it did not have, at a cost of a few lines. A model must now copy a figure rather than paraphrase it, so a value reading "about twenty thousand" on a quote saying "USD 20,000" is refused and asked again, which is a real narrowing accepted deliberately. The known limit is written into the specification and pinned by a test that asserts it, so it is a recorded fact rather than a comment that could rot. Anyone reading a card should understand that a checked quote means the sentence is really on the page, and not that the value is right.
