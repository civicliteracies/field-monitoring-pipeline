# ADR-0025 — The conventional layout for decision records and specifications [decision]
**Status:** Accepted (2026-09-01). **Owner:** CLI. Supersedes in part [ADR-0003](0003-adopt-numbered-adrs-for-the-decision-log.md), and supersedes [ADR-0017](0017-bug-history-is-a-separate-file.md).
**Context.** A review against published conventions found four places where this repository had invented a name for something that already has a standard one. Decision records are conventionally one file per record under `docs/decisions/`, numbered, titled with dashes, with an index beside them; here they were twenty-four records in a single file, which meant every new record arrived as a diff against a long document and the file was already at the length where people stop opening it. Specifications conventionally sit in `specs/`, which is the layout used by the spec-driven tooling this project's Constitution pattern comes from; here the folder was called `issues/`, which is also GitHub's own name for its bug and task tracker, so the name pointed a reader at the wrong thing. A file recording defects has no convention at all: the usual arrangement is the tracker while a defect is open, a changelog line once it is fixed, and the rule about tests in the contributing guide. And a changelog is conventionally opened before the first release rather than reconstructed after it. Each departure carries the same cost, which is that someone who already knows the convention has to learn this project's version instead. None of the four had been published, so the change costs one edit and breaks no link that exists anywhere.
**Decision.** Adopt the conventional layout. The records move to `docs/decisions/NNNN-title-with-dashes.md`, one file each, with `docs/decisions/README.md` as the index; the text of every record moves unchanged, and only the Status field of a superseded record is touched, which is the field that exists to change. `issues/` becomes `specs/`, and the specification is numbered rather than dated, because git already carries the date. `CHANGELOG.md` is added at the root in the Keep a Changelog format, opening with an Unreleased section. `docs/BUGS.md` is retired: an open defect goes in the repository's issue tracker, a fixed one gets a line under Fixed in the changelog, and the rule that a fix must add a test failing on the pre-change behaviour moves into `CONTRIBUTING.md` and stays in `AGENTS.md`. The two entries it held were specification defects found before any code existed, and the rules they established are already recorded as [ADR-0001](0001-deadline-validates-as-a-valid-date.md) and [ADR-0002](0002-heartbeat-proves-liveness-not-emptiness.md). `constitution.md` keeps its name and its place at the root, with one line naming the pattern it follows so that it reads as a known thing rather than an invention.
**Consequences.** Every folder name here is now one an experienced developer has seen before, which is the whole point: the repository stops asking to be learned. Adding a record becomes a commit that creates one file and touches nothing else, so the reasoning reviews cleanly on its own. Three things are given up. The reasoning can no longer be read top to bottom in one scroll, which the index covers in part but not wholly. A defect no longer gets a written symptom, cause, fix and test as a matter of course; where one deserves that depth it becomes a record here, which is the conventional home for it. And record filenames become effectively permanent, because renaming one breaks every link to it, which suits the immutability rule this log already follows. The threshold rule, the format of a record, and the rule that accepted records are never rewritten are all unchanged.
