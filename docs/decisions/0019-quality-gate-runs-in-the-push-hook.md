# ADR-0019 — The quality gate runs in the push hook, and `verify` is its read-only form [decision]
**Status:** Accepted (2026-08-31). **Owner:** CLI.
**Context.** PR 1 was specified to make `mise run check` binding by requiring it as a status check on `main`. A required CI check earns its place when you cannot control whether contributors run the tests; at this team size everyone can agree to run them, so the check would largely duplicate what already happens locally. Two facts made the local route weaker than it looked. The pre-push hook ran `pytest` alone, so strict type-checking ran nowhere automatic. And `mise run check` fixes as it goes, depending on `ruff format .` and `ruff check . --fix`, both of which rewrite files, which is wrong for anything acting as a gate.
**Decision.** The pre-push hook runs the whole gate through one mise task, so there is one definition of it rather than two that drift. The Stop hook of [ADR-0009](0009-second-opinion-review-agent-and-stop-hook.md) moves to the same task, which is why that record is superseded in part. A second task, `verify`, is the read-only form: it checks formatting rather than applying it, lints without fixing, type-checks, and runs the tests. `check` stays as the developer task that repairs as it goes; `verify` is what hooks and any CI run.
**Consequences.** Strict type-checking now runs before every push, which it did not. A gate can no longer pass by quietly rewriting the code it is judging, which the old arrangement allowed. `--no-verify` still bypasses the hook, and that is accepted: a bypassed push lands on a branch, and `main` takes changes only through a pull request, so the blast radius is a branch nobody merges unreviewed. Whether CI also runs `verify` on pull requests, and whether it becomes a required status check, is open and is CLI's call.
