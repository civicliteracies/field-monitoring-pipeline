# ADR-0038 — The contact check runs wherever a published value is made, not at one of the places [decision]
**Status:** Accepted (2026-09-07). **Owner:** CLI.
**Context.** This project promises that a published card carries no personal contact detail, and keeps contact details in the raw archive instead. An audit of fourteen independent readings, every finding reproduced by running the code before it was accepted, found that the promise was enforced in exactly one place. The rule ran on the quote and on nothing else. The title, the funder and all four stored values passed through a guard that looked only for control characters, so a telephone number written into any of them reached the record untouched. The funder was the widest way through, because ADR-0032 deliberately leaves it ungrounded in phase one, which means the model's own words become a stored value with nothing reading them. Reproduced end to end: a funder of "Example Trust (grants team, tel +45 20 41 23 45)" and a title of "Call the grants team on 020 7123 4567" both built a record. The same audit found four separate ways past the rule itself, all of them in code written the day before to close an earlier version of the same hole. A currency word at either end of a run of digits cleared every number between them, because each number was weighed against the two ends of the whole run rather than against its own surroundings. A run short enough to be one number was never broken at all, so one currency word cleared a number beside an amount. Two numbers a single space apart merged into a run longer than anybody's number and were discarded for being too long to ring, which made the rule weakest exactly where a page puts a number, in a contact line. And the pattern that finds a candidate knew only the plain ASCII separators, so an en dash, a non-breaking hyphen, a minus sign, a solidus, a middle dot, a word joiner, a wide digit or this project's own paragraph boundary character each hid a number completely, with no currency word needed anywhere.
**Decision.** The contact rule runs where a published value is made. It is applied in the one function every stored value already passes through on its way into the record, so the title, the funder and all four values are held to the same rule as the quote beside them. The rule itself is rewritten rather than patched a fifth time. Every character that is one of these written another way is read as the plain one first, by a mapping in which each character stands for exactly one character so that a position in the plainly written text is the same position in the sentence a page wrote. Every run is broken into its separate numbers, not only a run already too long, because breaking every run was measured against every sentence this project has written down and changed no answer. Each number carries its own position, so the currency rule looks at what sits beside that number rather than at the ends of the run it was found in. A part still holding more digits than anybody's number, with nothing inside it that a single number cannot carry on across, is refused rather than skipped. An address written to defeat a machine reading the page is refused as well, and the bare spelt out form counts only when both markers are spelt out together, so an ordinary sentence saying "look at the guidance" is not mistaken for one. The version stamped on the deterministic side is deliberately not bumped: it has never produced a stored record, because the step that writes the first card has not been built, so there is nothing for a later reader to tell apart and a bump would ask for a rebuild of nothing.
**Consequences.** The check now refuses a value or a quote in more places than before, and every refusal costs one further attempt and at worst a field recorded as not stated. That direction is deliberate and it is the same trade ADR-0037 recorded: refusing an honest sentence is recoverable, and publishing somebody's telephone number into a repository that keeps its history is not. Two costs are named rather than left to be discovered. Reading a solidus as a separator inside a run of digits made a date written as 2026/09/30 look like a number to ring, which was caught by this change's own test and settled by teaching the shapes that are known not to be numbers about a date written year first with any of the three separators. And the bare figure with no currency beside it is still refused, exactly as ADR-0037 accepted; that was checked again here and deliberately left alone. Forty six new tests cover the change, taking the suite from 271 to 317. Twenty five of them were run against the previous code and fail on it, and the rest were each checked against the behaviour they replace, which is what this project means by a fix. See BUG-030 through BUG-035, BUG-037, ADR-0037, ADR-0031 and ADR-0032.
