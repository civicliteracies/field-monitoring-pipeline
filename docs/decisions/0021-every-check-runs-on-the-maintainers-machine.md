# ADR-0021 — Every check runs on the maintainer's machine; GitHub runs only the scheduled job [decision]
**Status:** Accepted (2026-08-31). **Owner:** CLI.
**Context.** PR 1 was built around a quality gate running on GitHub, carrying the tests, the documentation guard, a library vulnerability scan, a check that the two dependency files agree, and the file size budget, alongside a weekly security-scoring workflow and automatic dependency update proposals. CLI's position is that checks on a build server earn their place when you cannot control whether contributors run them on their own machines, which is the situation of a large team or an open project accepting changes from strangers. Neither describes this project: three people, all of whose machines are known, who can simply agree to run the checks. Here the purpose of GitHub Actions is to run the scraping and data processing on a schedule, and anything beyond that is overhead. One claim of the build's, that the documentation guard could only run against a pull request, was tested and found false: what it needs is a base branch to compare against, and `main` supplies that.
**Decision.** Every check runs on the maintainer's machine, inside `mise run verify`, which the pre-push hook runs. `.github/workflows/ci.yml`, `.github/workflows/scorecard.yml`, and `.github/dependabot.yml` are deleted. GitHub Actions is reserved for the scheduled run, which arrives at PR 2. The checks that lived in CI move into `verify`: the lockfile agreement check, the library vulnerability scan, the file size budget, and the documentation guard, the last two as scripts under `scripts/`.
**Consequences.** One definition of the gate, in one place, run before anything leaves the machine. Nothing red can be merged because nothing red can be pushed, unless the hook is deliberately bypassed, and a bypassed push lands on a branch rather than on `main`. Three things are given up, deliberately. The checks no longer run on Linux, so a difference between the build machine and the server would not surface until the scheduled run exercises it, which is the class of fault that made `.gitattributes` necessary. The vulnerability scan runs only when someone pushes, so a hole found in a library during a quiet week goes unnoticed until the next push; the Dependabot alerts repository setting covers that and is worth CLI turning on. And there is no independent second opinion on a change, which is the thing a build server genuinely provides for a project taking changes from strangers. All three are accepted at this team size. Supersedes [ADR-0020](0020-ci-runs-the-gate-and-reports.md), and supersedes the parts of [ADR-0004](0004-clean-as-you-code-machine-gate.md) and [ADR-0008](0008-free-supply-chain-stack-on-the-public-repo.md) that placed these checks on GitHub.
