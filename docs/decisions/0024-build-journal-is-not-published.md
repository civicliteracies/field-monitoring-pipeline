# ADR-0024 — The build journal is not published; it lives with the team [decision]
**Status:** Accepted (2026-08-31). Superseded in part by [ADR-0025](0025-conventional-file-layout.md), which retired `docs/BUGS.md` as one of the three public records. **Owner:** CLI. Supersedes [ADR-0016](0016-one-activity-log-replaces-the-worklog-folder.md).
**Context.** [ADR-0016](0016-one-activity-log-replaces-the-worklog-folder.md) made `docs/ACTIVITY.md` the project's journal, one running file recording what was done and when. In practice almost everything in it that concerned the system was already a numbered record here, and what was unique to it was a narrative of how the work was done: which documents were read on which day, which tools were installed, which mistakes the build made and corrected. This repository's own rule asks one question of anything written in it, whether the sentence describes the published thing or describes how we made it, and a journal is the second by definition. The file was also where nearly every breach of that rule was found, which is not a coincidence: process narrative is where people, access, and internal documents naturally appear. Git already publishes what was done and when, per commit, with an author and a date, so the journal was a second copy of that which could drift and which alone could leak.
**Decision.** `docs/ACTIVITY.md` is removed from the repository and its content moves to the team's private notes, where the journal continues. Three records stay public because each describes the system rather than its making: `docs/ARCHITECTURE.md` for what each file is, `docs/DECISIONS.md` for why each choice was made and what it costs, and `docs/BUGS.md` for what broke and the test that now guards it.
**Consequences.** The rule now has one fewer standing exception to police, and the file most likely to carry a name, an access detail, or an internal reference is gone. A maintainer inheriting this loses the day-by-day story and keeps the three records that answer what, why, and what broke, which is what maintaining it actually requires. The commit history remains the public record of what shipped and when. The threshold rule changes with it: where an ordinary slice previously needed an activity line, it now needs nothing beyond its commit, and a full record is still required when a change touches the item schema, the extraction step, a source route, or the cron cadence, or when a member of CLI makes a call with real alternatives.
