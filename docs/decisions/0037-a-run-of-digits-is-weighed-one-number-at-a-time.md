# ADR-0037 — A run of digits is weighed one number at a time, and a solid run is not assumed to be money [decision]
**Status:** Accepted (2026-09-05). **Owner:** CLI.
**Context.** A stored quote is published in a repository that keeps its history, so it must carry no telephone number. The deterministic check that enforces this had two faults, both found by an audit and its own skeptics, and both reproduced by running the code. The first: a run of digits does not stop where a telephone number stops. The pattern that finds a candidate continues through a bracket or a second number, so a number followed by its opening hours became one run of nineteen digits, the length test said no number is that long, and the whole quote published. Five of six ordinary sentence shapes leaked this way, including one built from this project's own first funder's contact line. The second: any unbroken run of seven or eight digits was waved through as an amount written without separators. That exemption made every telephone number written the same way invisible. Four independent lines of research were run on the second question before deciding it. ITU-T Recommendation E.164 sets a maximum of fifteen digits and no minimum at all for an ordinary national number, so the seven digit floor was a local judgement that the code presented as a standard. Denmark's national language authority lists the solid eight digit form first among the correct ways to write a telephone number there, and Danish and Norwegian funders are on this project's watch list. Google's phone number library, the reference implementation of this problem, accepts a solid block at every level of strictness it offers, so the absence of separators is not evidence of anything. And the European Data Protection Board names pattern based filtering of telephone numbers as a data minimisation measure, while Article 25(2) requires that ambiguity be settled towards not making personal data available to an indefinite number of people. The exemption only ever fired where no currency marker had been found, which made it precisely the rule that settled ambiguity, settling it the other way.
**Decision.** A candidate run short enough to be one telephone number is weighed whole, exactly as before. A run longer than the maximum is broken at the places a single number cannot continue across, which are a bracket, a gap of more than one space, a dash with space on both sides, and a plus that starts a second number, and each part is then weighed on its own. The exemption for a solid run of seven or eight digits is removed. A date written solid joins the shapes that are known not to be numbers to ring, written tightly as a plausible year with a real month and a real day so that it clears a date without clearing every eight digit number again. The currency rule is deliberately left exactly as it is. Three of the four research lines proposed widening it, by adding tokens or by looking across a whole sentence, and both skeptics measured that and found it makes the check leakier: a sentence naming an amount and a person's number would stop being refused. It is the one place a real telephone number can still escape, and widening it later should get the same scrutiny this decision got.
**Consequences.** The check now refuses an amount written solid with no currency marker beside it, which it previously allowed. That is the accepted cost and it is written into a test rather than left to be discovered: refusing an amount costs a second attempt and, at worst, a field recorded as not stated, while publishing a telephone number cannot be taken back. Naming the currency clears it, which is how a funder writes an amount in practice, and measurement on both frozen pages found no bare seven or eight digit run at all. Two things were checked and found not to apply, so that a later reader does not have to check them again. Link addresses never reach the checked text, because the derivation keeps only what a page displays and drops every attribute, so a `tel:` address cannot arrive by that route. And no new dependency is added: adopting the phone number library was considered and refused, because it needs a hand maintained list of which countries to expect, which is the kind of thing that rots quietly. See BUG-029 and ADR-0031.
