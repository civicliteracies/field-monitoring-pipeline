# ADR-0018 — The scheduled run commits to its own branch, not to `main` [decision]
**Status:** Accepted (2026-08-31). **Owner:** CLI.
**Context.** The original design had the automated run committing its cards and generated surfaces to the default branch, with CLI working on its own branches so the two never edit the same branch at once. A ruleset applied on 2026-08-30 requires a pull request for every change to `main`, and that rule binds automation as well as people: a workflow pushing with the default token is refused with `Changes must be made through a pull request`. Letting a workflow through reliably means an exception on the ruleset backed by a GitHub App token or a personal access token, which is a further moving part and a further secret.
**Decision.** The scheduled run commits to its own branch rather than to `main`. Nothing is added to the ruleset's bypass list, and `main` keeps the pull request rule for everyone and everything.
**Consequences.** The separation the original design wanted is unchanged, with the branches the other way round: people own `main`, the run owns its own branch, and the two still never edit the same branch at once. No bypass actor, no GitHub App, no extra secret, which is what the boring-technology rule in the Constitution asks for. The feed and the dashboard read from the run's branch; `raw.githubusercontent.com` and the contents API both return `Access-Control-Allow-Origin: *`, so a static page can read across branches, and serving GitHub Pages from a branch is an established pattern. The branch name and the exact route the surfaces take are settled at PR 11 and PR 12. Supersedes the original design, in which the run committed to the default branch.
