# ADR-0026 — Item names are always hashed, never taken from a source [decision]
**Status:** Accepted (2026-09-01), and superseded in part by [ADR-0028](0028-a-name-identifies-one-sources-capture.md), which added the source to what every rule hashes. That every name is a hash, and the three rules and their order, still hold. **Owner:** CLI. No earlier record states the keying rule; it lived in `AGENTS.md`, which is corrected in the same change.
**Context.** An item's name is its filename, and the archive is keyed by it. The original rule set an order of preference: the source's own identifier for the item where it publishes one, else the canonical link, else the body. The first of those reads a value out of a feed, which is text from the open web and is influenced by whoever controls the source. That value then becomes part of a file path. A source publishing an item identified as `../../config/sources.toml` would, taken literally, write outside the archive and over the watch list. [ADR-0010](0010-ai-step-readiness-gate.md) already treats fetched text as untrusted where it reaches the model, but nothing extended that to fetched text that becomes a path.
**Decision.** Every rule hashes its input. The three rules and their order of preference are unchanged; only the output shape changes. A name is therefore always a fixed-length hexadecimal string, whichever rule produced it. The companion record beside each item states which rule was used, so the store can still say how any name was derived.
**Consequences.** A name cannot contain a path separator, so it cannot address anything outside the archive. That removes the class of fault rather than checking for it: there is no sanitising step to write, no check that a later change could forget, and nothing that depends on a caller remembering the rule. The archive is also uniform, every name the same shape, which makes a stray file obvious. What is given up is legibility: a name no longer hints at the item it belongs to, and the companion record has to be opened to see where a file came from. That was already true for two of the three rules. Departs from the keying rule as written in `AGENTS.md`, which is corrected in the same change.
